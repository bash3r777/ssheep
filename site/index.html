ssheep

One binary. One file. One key.

Very early software: no audit, not secure, expect the protocol to move. How it works.

Control a flock of machines — your own boxes, wherever they are — without opening a port, without an account, and without trusting anybody's server.

Install

Download Source

Linux, macOS and Windows, amd64 and arm64. Static, nothing to install alongside it.

Use — three steps

ssheep — set up a flock
step 1  on the machine you control from:
$ ssheep master
👑  master ready — flock "myflock"
    connectors  relay.ssheep.xyz:7000

    run this on each machine you want in the flock:
      ssheep sheep "H4sIAAAA…"
    run this on the machine with a public address:
      ssheep connector "H4sIAAAA…"

step 2  paste that, on each machine:
$ ssheep sheep "H4sIAAAA…"
🐑  this machine is in the flock

step 3  back on the master:
$ ssheep run --all -- uptime
sheep-1|  14:22:01 up 3 days,  2:14,  load average: 0.08
sheep-2|  14:22:01 up 12 days, 4:02,  load average: 0.31
❯

That is the whole setup. The connector works out its own address and tells the flock, so there is no address or fingerprint to copy anywhere.

For humans

👑master — holds the flock key, mints tickets, runs commands. Needs no reachable address, so it can be a laptop that is usually off.
🐑sheep — a machine in the flock. Only ever dials out. Holds nothing but its own key.
📡connector — a blind relay and address book, and a member of the flock like anything else. The only role needing a reachable address.

It is one binary; the role is the subcommand. Every default can be changed — flock name, relay, how many tickets, the port. More, for humans.
