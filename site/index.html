ssheep

One binary. One file. One key.

Very early. Not secure. This is a working prototype, published because it is useful, not because it is safe. There has been no audit. Do not use it for anything you would be upset to lose. Expect the protocol to change.

Control a flock of machines — your own boxes, wherever they are — without opening a port, without an account, and without trusting anybody's server.

Three things

👑 masterHolds the flock key, mints tickets, runs commands. Can sit behind a NAT, switched off most of the time.
🐑 sheepA machine in the flock. Only ever dials out. Holds nothing but its own key.
📡 connectorA blind relay and address book, and a member of the flock like anything else. The only role needing a reachable address — and it can be any machine.

Install

curl -fsSL https://ssheep.xyz/install.sh | sh

Download Source

Static binaries for Linux, macOS and Windows, amd64 and arm64. Nothing to install alongside it.

Use

On the machine you will control the flock from — the 👑 master:

ssheep master

That sets everything up and prints two things. Paste the first on every machine you want in the flock — one ticket each:

ssheep sheep "H4sIAAAA…"

And the second on the one machine with a public address, usually a small VPS:

ssheep connector "H4sIAAAA…"

That is the whole setup. The connector tells the master where it is, so there is no address or fingerprint to copy anywhere. Then:

ssheep see
ssheep run --all -- uptime

For humans

Read how it works — the roster, the keys, what the connector can and cannot see, and what is deliberately missing. The full architecture notes live in the repo at docs/ARCHITECTURE.md.

For agents

/agents.txt is a short, machine-readable version of this page: what the tool is, how to install it, and the exact commands, with no prose to wade through. Pointing a coding agent at that file is enough for it to operate a flock.
